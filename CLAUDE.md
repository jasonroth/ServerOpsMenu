## Project Overview

**ServerOpsMenu** is a Windows PowerShell module that presents an interactive, text-based operations menu for managing Windows servers. It targets service desk personnel who need to perform routine server administration tasks (services, processes, disk, event logs, reboots) without requiring deep PowerShell knowledge.

The module supports both **local** and **remote** server management via PowerShell Remoting (`New-PSSession` / `Invoke-Command`).

- **Module version:** 0.1.1
- **Author:** @jason_roth
- **PowerShell requirement:** 3.0+
- **Platform:** Windows only (relies on WMI/CIM, Win32 classes, Windows Event Log)
- **Published to:** PowerShell Gallery (`Install-Module ServerOpsMenu`)

## How the Module Works

### Module Loading (`ServerOpsMenu.psm1`)

The root module file dot-sources every `.ps1` file found under `Public\` and `Private\` at import time. Only functions whose basenames match files under `Public\` are exported via `Export-ModuleMember`.

### Public API

**`Invoke-Menu`** (`Public/Invoke-Menu.ps1`) is the only exported function.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `ComputerName` | `string[]` | No | Remote server(s) to manage |
| `Credential` | `PSCredential` | No | Credentials for remote session |
| `Path` | `string` | No | Path to the CliXml menu file (default: `ServerTasks.xml`) |

**Execution flow:**
1. If `ComputerName` is provided, creates a `PSSession` to the remote host.
2. Calls `Get-MOTD` to display an ASCII art banner with live system stats.
3. Loads the menu from `ServerTasks.xml` (`Import-Clixml`).
4. Renders a numbered menu and loops on `Read-Host`, executing the selected action's stored scriptblock via `Invoke-Command`.
5. Exits on `Q` (or any input starting with `q`).

### Menu Definition (`Private/New-Menu.ps1`)

`New-Menu.ps1` is a **one-shot configuration script** (not a function). Run it to regenerate `ServerTasks.xml`. It:
1. Defines an ordered hashtable mapping menu item labels to scriptblocks.
2. Converts the hashtable to `[pscustomobject]` items with `ItemNumber`, `MenuItem`, and `Action` properties.
3. Exports the resulting object to `ServerTasks.xml` via `Export-Clixml`.

**Current menu items** (in order):
1. Get Services — `Get-SOMService | Format-Table`
2. Restart Service — `Restart-SOMService`
3. Get Top 5 Processes by CPU — `Get-SOMProcess -Property CPU`
4. Get Top 5 Processes by Memory — `Get-SOMProcess -Property Memory`
5. Stop Process — `Stop-SOMProcess -Verbose`
6. Restart Process — `Restart-SOMProcess -Verbose`
7. Get Volumes — `Get-SOMVolume`
8. Get Recent System Eventlog — `Get-SOMEventLog -ComputerName $ComputerName -Credential $Credential | Format-Table -AutoSize`
9. Restart Server — `Restart-Computer -Confirm -Force`

> **Note:** To add or remove menu items, edit `New-Menu.ps1` and re-run it to regenerate `ServerTasks.xml`.

### Private Functions

| Function | Description |
|----------|-------------|
| `Get-MOTD` | Displays a colored ASCII art Windows logo with live system info (OS, hostname, kernel, uptime, shell, CPU, process count, memory, system volume). Supports remote execution. |
| `Get-SOMService` | Returns all services via `Get-CimInstance Win32_Service` with DisplayName, Name, StartMode, State, Status. |
| `Get-SOMVolume` | Returns fixed drives (DriveType 3) via `Get-CimInstance Win32_LogicalDisk` with ID, VolumeName, and disk usage. |
| `Get-SOMProcess` | Returns top 5 processes sorted by CPU percentage or memory (MB). Requires `-Property CPU` or `-Property Memory`. |
| `Get-SOMEventLog` | Returns the 50 most recent System event log entries. Supports optional `ComputerName` and `Credential` for remote access. Uses the older `Get-Eventlog` cmdlet. |
| `Restart-SOMService` | Stops then starts a service by name. Uses `-Confirm` on Stop-Service. |
| `Stop-SOMProcess` | Stops a process by name with `Stop-Process -Confirm -Force`. |
| `Restart-SOMProcess` | Stops a process, retrieves its original command line via WMI, then relaunches it. Uses `Get-WmiObject Win32_Process`. |

## Development Conventions

### Function Naming

- **Public functions** use standard PowerShell approved verbs: `Invoke-`
- **Private functions** use the `SOM` prefix (Server Operations Menu): `Get-SOM*`, `Restart-SOM*`, `Stop-SOM*`
- Follow PowerShell's approved verb list (`Get-Verb`) for any new functions

### Function Structure

All functions follow the standard PowerShell pattern:

```powershell
Function Verb-SOMNoun {
    <#
        .SYNOPSIS
        .DESCRIPTION
        .PARAMETER
        .EXAMPLE
        .VERSION
    #>
    [CmdletBinding()]
    Param ( ... )

    Begin {}
    Process { ... }
    End {}
}
```

- Always include `[CmdletBinding()]` for advanced functions
- Use the `Begin`/`Process`/`End` block structure even when `Begin` and `End` are empty
- Include comment-based help (`.SYNOPSIS`, `.DESCRIPTION`, `.PARAMETER`, `.EXAMPLE`, `.VERSION`)

### Parameters

- Use `[ValidateSet(...)]` for constrained choices (e.g., `"CPU"`, `"Memory"`)
- Use `[ValidateNotNullOrEmpty()]` on mandatory string inputs
- Use `[ValidateScript({...})]` for path validation
- Support `ValueFromPipeline=$true` and `ValueFromPipelineByPropertyName=$true` where appropriate
- Use `[PsCredential][System.Management.Automation.CredentialAttribute()]` for credential parameters

### Splatting

Use hashtable splatting for cmdlets with optional parameters rather than long parameter lists:

```powershell
$Params = @{
    ComputerName = $ComputerName
    ErrorAction  = 'Stop'
}
if ($Credential) { $Params.Add('Credential', $Credential) }
SomeCmdlet @Params
```

### Error Handling

- Wrap remote session creation and remote execution in `try/catch`
- Use `Write-Warning` to surface errors to the user
- Use `Write-Verbose` for diagnostic/debug messages (not user-facing errors)
- Use `ErrorAction = 'Stop'` on critical calls to ensure exceptions are catchable
- Use `-Confirm` on destructive operations (Stop-Service, Stop-Process, Restart-Computer)

### Output and Display

- Use `Write-Host` with `-ForegroundColor` for user-facing colored output (Green = success, Red/Yellow = art/warnings)
- Return objects from functions; let the caller format with `Format-Table`, `Out-Host`, etc.
- Return `[pscustomobject]` with explicit property names instead of raw WMI/CIM objects

### Remote Execution Pattern

Functions that need to support remote execution should:
1. Accept `ComputerName` and `Credential` parameters
2. Build a `$PSSessionParams` hashtable
3. Create a `New-PSSession` and store it
4. Build a `$CommandParams` hashtable with `ScriptBlock`
5. Add `Session = $RemoteSession` to `$CommandParams` when remoting
6. Execute via `Invoke-Command @CommandParams`

## Regenerating the Menu XML

`ServerTasks.xml` is a pre-built CliXml artifact. To rebuild it after editing menu items:

```powershell
# From the module root directory
. .\Private\New-Menu.ps1
```

This overwrites `ServerTasks.xml` in the working directory.

## Installation and Usage

```powershell
# From PowerShell Gallery
Install-Module ServerOpsMenu

# Import the module
Import-Module ServerOpsMenu

# Launch menu for local machine
Invoke-Menu

# Launch menu for a remote server
Invoke-Menu -ComputerName 'Server1.contoso.com'

# Launch with explicit credentials
Invoke-Menu -ComputerName 'Server1.contoso.com' -Credential (Get-Credential)
```

> **Note:** The `#Requires -RunAsAdministrator` line in `Invoke-Menu.ps1` is currently commented out. Many operations (CIM queries, service restarts, process stops) require elevated privileges.

## Known Issues and Notes

- `Get-MOTD.ps1` and `ServerOpsMenu.psd1` are saved in UTF-16 encoding (Windows legacy). This is functional but unusual; new files should use UTF-8.
- `Restart-SOMProcess` uses the legacy `Get-WmiObject` cmdlet instead of `Get-CimInstance`. Consider migrating to `Get-CimInstance Win32_Process` for consistency.
- `Get-SOMEventLog` uses `Get-Eventlog` (deprecated in PowerShell 6+) instead of `Get-WinEvent`. This limits compatibility to Windows PowerShell 5.x.
- `en-US/about_IHGServerOps.help.txt` is empty; the help text has not been written.
- `ServerOpsMenu.ps1xml` (type formatting) is empty; custom type formatting has not been implemented.
- There is no CI/CD pipeline, linter configuration, or build script.
- `ADTasks.xml` under `Private/` appears unused.

## File Encoding Notes

Some files in this repository use UTF-16 LE encoding (a Windows PowerShell ISE default):
- `ServerOpsMenu.psd1`
- `Private/Get-MOTD.ps1`

When editing these files, preserve their encoding to avoid module load failures. New files should use **UTF-8 without BOM**.
